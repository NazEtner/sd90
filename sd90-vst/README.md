# sd90-vst

<p>
<img src="../assets/trademarks/vst-compatible.png" alt="VST Compatible" width="120">
</p>

EDIROL SD-90 を、DAW から「普通のソフトシンセ」として扱えるようにするプラグインです。
デバイスを扱う層は [`sd90-rs`](../sd90-rs) にあります。

現状、SD-90 を DAW で使うには、オーディオドライバで音を取り込む / MIDI ポートを別途用意する /
トラックの遅延を手作業で合わせる、という 3 つを人間がつなぎ合わせる必要があります。仮想 MIDI ポートを
追加しても、いちばん面倒な**手作業でのレイテンシ合わせ**は残ります。

MIDI 入力と音声出力を 1 つのプラグインにまとめれば、遅延の申告はプラグインの
役目になり、位置合わせはホストの PDC が行ってくれます。専用のオーディオドライバも仮想 MIDI ポートも
不要になります。

```
DAW の MIDI イベント          RT スレッド          送出スレッド        SD-90
 process() の inputEvents ---> 4byte パケット + ---> デバイスフレーム ---> IF2 bulk
   (sampleOffset 付き)          送出フレーム        まで待って送る       EP 0x02

 process() の出力バッファ <--- Hermite 補間で <--- ring (24bit 詰め) <--- IF1 iso IN
   (f32 stereo)                 ドリフト吸収                             EP 0x81
```

iso OUT (IF0) は使いません。VST® 3 プラグインは音をデバイスに送る必要がないので、`StreamCfg::capture_only`
で IF0 の alt を切り替えずに動かします。

## 現在の状況

VST3 プラグインとしては一通り動作します。DAW での動作確認はこれからです。

* `engine.rs` / `resample.rs` … 実機で検証済み
* `vst3/` / `plugin.rs` / `factory.rs` … VST3 の外枠。手書き
* `main.rs` … 3 種類のプローブ (内部を直接呼び出すもの / DLL 経由の最小 VST3 ホスト / エディタ)
* `gui/` / `sd90.rs` / `tones.rs` / `control.rs` … 専用エディタと状態の保存 (下の「エディタ」を参照)

未実装のもの: DIN IN のイベント出力、MFX / リバーブ / コーラスの詳細パラメータ
(現状はタイプとレベルのみ)、GS / XGlite の音色名。

## エディタ

本体のパネルと Owner's Manual の章立てに合わせた構成にしています。仕様の出典は Roland の
公式 PDF 3 点 (Owner's Manual `SD-90_OM.pdf` / MIDI Implementation
`SD-90_MI.pdf` / Parameter List `SD-90_PR.pdf`) です。

| 画面 | 内容 | 出典 |
| --- | --- | --- |
| 上段 | 音源モード (GM2 / Native / GS / XGlite)、接続状態、出力メータ、PANIC | OM p.20, p.77 |
| 左 | 32 パート (A01-B16)。INST/DRUM、セット、番号、音色名、M / S | OM p.19-27 |
| INST/DRUM SET | 音色選択 + PREVIEW、パートパラメータ一式 (Native 専用分を含む) | OM p.21-37 |
| EFFECTS | リバーブ / コーラス (GM2 は GM2 のタイプ)、MFX-A/B/C (Native)、EQ | OM p.38-47 |
| ALL | Master Volume / Fine (Hz) / Coarse | OM p.31, p.37 |
| SYSTEM | Device ID、一括送信、INIT、診断 | OM p.70, p.72 |

メッセージの使い分けはマニュアルの記述に従っています。音色は Bank Select + Program Change
(GM2 の音色セットのみ DT1 `10 00 pp 3F`)、それ以外のパートパラメータと
エフェクトは DT1、GM2 のリバーブ / コーラスのタイプは Universal Realtime の
Global Parameter Control で送ります。音色名の表は OM の付録 (p.129-134, p.139) から書き起こしました。

### 単体版 (`sd90-editor.exe`)

DAW を使わずにエディタだけを使うためのものです。SD-90 は本体に OUTPUT 端子とヘッドホン端子が
あるので、音色やエフェクトを調整するだけなら DAW は必要ありません。

```
cargo build --release      ルートの target\release\sd90-editor.exe ができる
```

中身はプラグインそのものです。DAW と同じ手順でプラグインを生成し、エディタを独自のウィンドウに
取り付けています (`src/standalone.rs`)。

音は Windows の既定の出力デバイスにも出力します (`src/audio.rs`)。WASAPI の共有
モード / イベント駆動で、**出力デバイスの時計に合わせて `process` を呼び出します** (DAW と同じ方式です)。
形式は 48kHz / float32 / ステレオで、デバイスのミックス形式が異なる場合は Windows に
変換させます (`AUTOCONVERTPCM`)。SD-90 と PC のサウンドデバイスの水晶のずれは、
プラグインのリサンプラが吸収します。最大ブロック長を 512 にしているので、申告レイテンシは
770 フレーム (16ms) です。出力デバイスが無い場合はタイマで駆動し、音は本体の端子からのみ出ます。設定は
`%APPDATA%\sd90-vst\standalone.state` に保存され、次に起動したときに本体へ送り直します。
[`sd90-rs`](../sd90-rs) のドライバや DAW 内のプラグインとは同時に使えません (デバイスを確保できない場合は OFFLINE の状態で起動します)。

### 画面上の鍵盤

右上の KEYBOARD で表示 / 非表示を切り替えます (単体版では最初から表示されています)。選択中のパートの
Port / Rx CH に送信します。送信経路はエディタの他の操作と同じ (`process` 経由) なので、
DAW の中で使っても DAW のノートと衝突しません (`src/gui/keyboard.rs`)。

* マウス: 押すと音が鳴り、押したまま横に動かすとグリッサンドになります
* PC のキーボード: `Z S X D C V G B H N J M ,` が下の段、`Q 2 W 3 E R 5 T 6 Y 7 U I` が 1 オクターブ上です
  (数値欄に入力している間は無効になります)
* OCT -/+、Vel、HOLD (CC#64)、ピッチベンド (離すと中央に戻ります)
* パートを切り替えたとき、鍵盤を閉じたとき、ウィンドウを閉じたときは、押さえている音をすべて離します

### エディタからの送信は必ず process を経由する

`MidiSched` は単一生産者のリングバッファで、送出スレッドは「フレームの昇順に積まれている」ことを
前提に、先頭から順に待ちます。UI スレッドが独自に積むと、DAW のノートを追い越したり、
未来のフレームに積んだものが後続をふさいだりします。そのため、エディタは `Control` の
送信待ちキューに置くだけにし、`process` が毎ブロック `try_lock` で取り出して
**そのブロックの先頭フレーム**に積むようにしています。取り出す量は DIN の速度 (3125 B/s) に
制限しています。モード切り替えの直後は 300ms の間隔を空けます。

### 状態の保存と送り直し

エディタの状態は `getState` / `setState` でプロジェクトに保存されます。エディタで何かを
操作すると「開いたときに送り直す」フラグが立ち、プロジェクトを開いたときと本体を確保し
直したときに、モード切り替えから始めて、初期値と異なる部分だけを送信します。何も操作して
いなければ何も送りません (曲頭の GM リセットなどは DAW 側のデータに任せます)。

### ウィンドウ

ホストの HWND の下に子ウィンドウを作成し、WGL 上で egui (glow) を描画します。
メッセージループはホストのものを使います。ウィンドウクラスは DLL の HINSTANCE で登録し、
最後のウィンドウを閉じたときに登録を解除します (EXE の HINSTANCE のままだと、DLL がアンロードされた後に
WNDPROC が無効なアドレスを指してしまいます)。GL のコンテキストは描画する間だけ current にし、描画後は元に戻します。

### ライセンス

GPL-3.0 (ワークスペース共通) です。VST3 の ABI 宣言 (`src/vst3/`) は `vst3_pluginterfaces` 3.8.1
をもとに書き起こしたもので、SDK は 3.8 から MIT ライセンスになっているため、GPL のコードに取り込めます。Steinberg の著作権表示は
`src/vst3/mod.rs` の冒頭に記載しています。

## レイテンシの決め方

プラグインは「イベントを先に受け取る」ことはできません。できるのは実際の遅れを
正しく申告することだけで、それさえ正しければ、ホストが他のトラックをずらして
タイミングを揃えてくれます。

* `B` … リングバッファの目標滞留量。出力は、ライブの取り込みから常に B だけ遅れます。
* `d` … 音源が MIDI を受信してから発音するまでの応答時間。**実測で 162 フレーム / 3.38ms** です。
* 申告レイテンシは **`L = B + d`** です。

このとき、ブロック先頭の読み出し位置を `R` とすると、
**sampleOffset が `k` のイベントは、デバイスフレーム `R + B + k` に送ればよい**ことになります。

導出は `engine.rs` の冒頭に書いてあります。要点は、ここにホストの時計が一切登場しないことです。
`R` はリングバッファの読み出し位置から厳密に決まり、`B` は定数です。デバイスのクロックを
参照するのは送出スレッドだけになります。

### B はブロック長を下回ってはいけない

ホストは 1 ブロック分を一度に取り出していくので、その瞬間にリングバッファにブロック長分の
データが無ければアンダーランになります。B を 4ms 固定にして 256 フレーム (5.33ms) のブロックで
動かすと、平均的な水位は足りていてもアンダーランが発生します。`safety_for(max_block)` は
`max_block + 96` (2ms) を返します。VST3 では `setupProcessing` の `maxSamplesPerBlock`
を渡してください。

### 水位が目標からずれたら、データを捨ててでも戻す

サーボによる引き戻しは、最大でも 0.2%/s しかありません。目標から数百フレームずれた状態を
放置すると数秒間ずれたままになり、その間は**申告レイテンシが実際の遅れと
一致しません**。その結果、ホストの PDC もその分だけずれてしまいます。

そこで、助走のやり直し時 (起動直後とアンダーランの直後) に余剰分をまとめて捨て、
水位をちょうど目標値から始めるようにしています。どのみちその時点で波形は途切れているので、
波形の連続性よりも申告値の正しさを優先しています。この処理を入れる前は、ブロック長 512 で
目標 608 に対して水位が 860 に張り付いていました (5ms のずれ)。

## ハマった点: リサンプラが 1 ブロックごとに 1 サンプル捨てても統計に現れない

補間のために取り出すフレーム数は
`floor(位相 + 比 x (n-1))` であり、`floor(位相 + 比 x n)` ではありません。後者だと
毎ブロック 1 フレーム多く取り出し、使わないまま捨ててしまいます。

厄介なのは、**サーボが比を緩めることで、水位だけは辻褄が合ってしまう**ことです。
水位もアンダーラン数も読み出し比も正常に見えたまま、波形にだけ不連続が生じます。
`sd90-rs` の「パケット記述子の Offset は転送ごとの相対値」と同じ種類の問題です。

プローブがブロック境界での段差を直接数えているのはこのためです。判定基準は
`iso.rs` の転送境界の検査と同じ (平均段差の 8 倍) ですが、**全体の平均ではなく
継ぎ目周辺の局所的な平均**で判定しています。減衰音のように区間内で振幅が 60dB 変化する
信号では、全体の平均が無音区間に引っ張られてしまい、うまく機能しないためです。

## ビルドとインストール

```
.\install.ps1              ルートの target\release にバンドルを組む
.\install.ps1 -Install     共通の VST3 フォルダに入れる (管理者権限)
```

`.vst3` は DLL 1 個ではなく**フォルダ**で、中身は次のようになっています。

```
SD-90.vst3\Contents\x86_64-win\SD-90.vst3    <- 拡張子 .vst3 の DLL
```

DLL 単体を置いても認識するホストはありますが、規格上はこちらの形式が正式です。

## 使い方

```
sd90-vst-probe [ms] [ブロック長] [out.wav] [B]     中身を直接回す
sd90-vst-probe vst3test [dll] [ms] [ブロック長]    DLL 越しに VST3 として回す
sd90-vst-probe editor [dll] [手順]                 エディタを開いて操作・撮影する
```

`vst3test` は、DAW も Steinberg の validator も使わずに、`LoadLibrary` →
`GetPluginFactory` → クラスファクトリ → `IComponent` / `IAudioProcessor` /
`IEditController` / `IMidiMapping` という一連の経路を呼び出します。`sd90-rs asiotest` と同じ役割のものです。

```
SD-90 / Audio Module Class / Instrument|Synth / SDK VST 3.8.1
音声出力: 1 本  [0] SD-90 (2ch, 既定で有効)
イベント入力: 4 本  [0] PART A  [1] PART B  [2] MIDI OUT 1  [3] MIDI OUT 2
パラメータ数: 8320
CC7 -> id 7 "PART A ch1 CC7"
setupProcessing(44.1kHz): 正しく断った
申告レイテンシ: 514 フレーム (10.71ms)
最後の release 後の参照数: 0
288000 フレーム / 左chピーク 0.0786 (-22.1 dBFS)
```

`vst3test` を付けない形式では、DAW も VST3 SDK も使わずに、「一定のブロック長で `pull` し続けながら、ブロック相対の
オフセットで MIDI を積む」という本番と同じ経路を実行します。`sd90-rs` 側の
ドライバ自己検証と同じ役割です。

鳴らす内容は環境変数で変更できます:

```
SD90_PROBE_CH=10 SD90_PROBE_PROG=- SD90_PROBE_NOTES=38,42
SD90_PROBE_RESET=-        GM System On を送らない
```

既定では、最初に **GM System On** を送ります。パートが無音になっている状態の個体でも、
これで鳴るようになります (実際、ch 1 が無音で ch 10 だけが鳴る状態から始まったことがありました)。

### 実測結果 (15 秒 x 4 条件, 弦楽器の和音を鳴らしながら)

| ブロック | B | アンダーラン | 水位 (目標) | 読み出し比 | 境界の不連続 |
| --- | --- | --- | --- | --- | --- |
| 128 | 224 | 0 | 224.2 (224) | 1.000046 | 1/5624 |
| 256 | 352 | 0 | 352.6 (352) | 1.000082 | 1/2811 |
| 512 | 608 | 0 | 607.9 (608) | 0.999989 | 1/1405 |
| 1024 | 1120 | 0 | 1120.5 (1120) | 1.000022 | 1/702 |

読み出し比が 1.0 から 100ppm 以内に収まっているのは、両者の水晶の差がその程度だということです。
境界の不連続が 1 件ずつあるのは、いずれもノートのアタックが継ぎ目に重なったものです。

なお、`sleep` に頼ってホストの動作を模倣してはいけません。Windows の既定のタイマ分解能は
15.6ms あり、10ms 程度のブロックだと 1 周期分まるごと寝過ごしてしまいます。実際のホストは
オーディオデバイスの割り込みで駆動されており、ここまで粗くはありません。粗いまま
測定すると、「ホストの模倣が不正確なために起きたアンダーラン」をプラグインの欠陥として
数えてしまいます。そのため、プローブは締め切りの 2ms 前からは CPU を譲るだけにしています。

## 前提

* 本体を Vendor モード (PID 0x0016) にし、Zadig で WinUSB を割り当てておくこと
* **`sd90-rs` のドライバとは併用できません。** どちらも IF1 の iso IN を占有するためです
* 音を出せるのは、1 プロセス内で 1 インスタンスだけです (録音バスが物理的に 1 系統しかないため)
