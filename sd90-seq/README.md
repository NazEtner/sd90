# sd90-seq

SMF を SD-90 で再生しながら、**同じ USB ケーブルでその音を録音します**。
デバイスを扱う層は [`sd90-rs`](../sd90-rs) にあります。

```
sd90-seq render <in.mid> [out.wav] [cable]
```

MIDI は IF2 の bulk、音声は IF1 の iso で扱います。どちらも同じデバイスなので、
「録音の何サンプル目でどのイベントを送ったか」が正確に分かります。

## 時計をデバイス側に置く

ホストの `Instant` を基準に送ると、SD-90 の水晶との ppm 単位の差が、3 分の曲で
数十ミリ秒に積み重なります。そこで **MIDI の送出位置は「取り込み済みフレーム数」で
決めています**。フレーム数の更新は 1 転送 (8ms) に 1 回しか来ないため、その間は
「最後に更新を確認してからの経過時間 x 48kHz」で補間します。位相はデバイスのクロックで
合わせ、その間だけをホストの時計で埋める形です。

実測した送出のずれは、平均 0.1〜1.4ms、最大 4ms 程度です。最大値が 4ms 付近に張り付く
のは 8ms という更新粒度によるもので、平均はそれよりずっと小さくなっています。

1ms 以内に並んだイベントは 1 回の転送にまとめます。和音の頭では数十個のイベントが
ほぼ同じ tick に集中するため、まとめないと USB の転送回数だけで遅れが出ます。

## out.wav.map

各イベントを録音のどのフレームで送ったかを書き出したファイルです。解析側はこれを読めば、
楽譜と波形を直接対応づけられます。

```
# sample_rate    48000
# t0_frame       72384
# frame  sec     bytes
72384   0.000000        b07f7f
75264   0.060000        903c64
```

## 前提

* SD-90 の MIDI StartUp を USB、SYSTEM の USB Driver を Vender にし、Zadig で WinUSB を割り当てておくこと
* 音源が反応しなくなった場合は、Native On (`F0 41 10 00 48 12 00 00 00 00 00 00 F7`)
  を送るか、本体の電源を入れ直してください。理由は sd90-rs の README を参照してください
