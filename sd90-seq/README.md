# sd90-seq

SMF を SD-90 に流しながら、**同じ USB ケーブルでその音を録る**。
デバイスを触る層は [`sd90-rs`](../sd90-rs) にある。

```
sd90-seq render <in.mid> [out.wav] [cable]
```

MIDI は IF2 の bulk、音は IF1 の iso。どちらも同じデバイスなので、
「録音の何サンプル目でどのイベントを送ったか」が確定する。

## 時計をデバイス側に置く

ホストの `Instant` を基準に送ると、SD-90 の水晶との ppm 差が 3 分の曲で
数十ミリ秒たまる。そこで **MIDI の送出位置を「取り込み済みフレーム数」で
決める**。フレーム数の更新は 1 転送 = 8ms に 1 回しか来ないので、その間は
「最後に更新を見てからの経過 x 48kHz」で補間する。位相はデバイスクロックで
合わせ、間だけホストの時計で埋める形。

実測の送出ずれは平均 0.1〜1.4ms / 最大 4ms 程度。最大値が 4ms 付近に張り付く
のは 8ms の更新粒度そのもので、平均はそれよりずっと小さい。

1ms 以内に並んだイベントは 1 転送にまとめる。和音の頭では数十イベントが
ほぼ同じ tick に来るので、まとめないと USB の転送回数だけで遅れる。

## out.wav.map

各イベントを録音のどのフレームで送ったかを書き出す。解析側はこれを読めば
楽譜と波形が直結する。

```
# sample_rate    48000
# t0_frame       72384
# frame  sec     bytes
72384   0.000000        b07f7f
75264   0.060000        903c64
```

## 前提

* SD-90 の MIDI StartUp = USB、SYSTEM の USB Driver は Vender、Zadig で WinUSB
* 音源が無反応になったら Native On (`F0 41 10 00 48 12 00 00 00 00 00 00 F7`)
  を送るか本体を入れ直す。理由は sd90-rs の README を参照
